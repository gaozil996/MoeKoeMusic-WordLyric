# word-lyric

全屏歌词逐字连贯填充 + 每首歌独立的快慢微调。

## 功能

**逐字连贯填充。** 一个字被颜色填满之后才进下一个字，速度取自歌词文件本身的
字内时间轴，不是均速。

MoeKoe 自带的逐字效果（`app.asar` 里的原始 CSS）是这样：

```css
.char {
  color: transparent;
  background: linear-gradient(to right, 主色 50%, 浅灰 50%);
  background-size: 200% 100%;
  background-position: 100%;
  -webkit-background-clip: text;
  transition: background-position .6s ease
}
.char.highlight { background-position: 0% }
```

靠 `background-position` 在 0.6 秒里从右滑到左 —— 观感上就是"整行匀速擦过去"。

这个插件把那条 transition 拆掉，改成一条渐变加硬边切在 `--lyc-p` 处，
由 JS 按每个字的真实起止时间逐帧更新。

**关键：不能碰 `color`。** 字形是 `transparent`，颜色全部来自背景裁剪；
一动 `color` 整行歌词直接消失。

**当前行判定用自己的时间轴（含偏移），不用 `.current-line-group`。**
后者按不含偏移的时间算，偏移生效后会卡住不动。

**KRC 解析。** 真实格式：

```
[764,1871]<0,305,0>王<305,252,0>大…
```

注意行首是 `[`，正则必须写成 `/^\[(\d+),(\d+)\](.*)$/`。
行尾带 `\r`，需要处理。时长确实不均匀 —— 实测 152 / 202 / 203 / 252 / 253 / 305 ms，
长音可达 3.3s。

**每首歌单独的快慢偏移。** 0.1 秒一步，存 `localStorage` 的 `lyc_off_<hash>`，
切歌独立、切回恢复。

## 设置

设置面板挂在 MoeKoe 自带的歌词设置面板里（右侧那个，鼠标移到最右边缘的
`◀` 把手展开），底部多一段可折叠的「歌词增强」。

可调：连续填充开关、已唱色 / 未唱色（色板）、歌词快慢 ±0.1 / 归零。

歌词快慢只有这一个入口。插件不再往歌词页左下角塞控制条，也不在播放条
或桌面歌词窗口里放按钮 —— 那两处都因为 `document.body` 兜底而跑到了
不该在的地方，详见下面「控制条为什么全删了」。

## 踩过的坑

**面板选择器搜不到。** Vue 生产构建把类名混淆了，`app.asar` 里也翻不到。
写探针挂进页面、按几何特征（右侧贴边、`position:fixed/absolute`）扫一遍
才定位到 `.fullscreen-lyrics-settings > .settings-panel`。

**面板默认收起。** 它一直在 DOM 里，只是 `transform: translate(280px)` 移出屏幕外，
加 `.open` 才滑进来。别因为 `querySelector` 找不到就断定不存在。

**点击会让面板收起。** 组件上挂了 `onFocusout: w => { w.currentTarget.contains(w.relatedTarget) || y() }`
—— 焦点一旦落到不可聚焦的元素上就回 body，Vue 判定为"离开了面板"。
所以所有控件都用原生可聚焦元素（`<button>` 而不是 `<div>`），并拦了一道
`focusout` 兜底。

**原生 `<input type="color">` 不能用。** 它会弹系统颜色对话框抢走焦点，一样触发收起。
改成 6 色预设色板，反而更顺手。

**控制条为什么全删了。** 曾经有两套面板外的速度控件，现在都没了：

1. 歌词页左下角的常驻条（`buildBar`）：`−0.1 / +0.1s / 归零`，和面板里的完全重复。
2. 播放条上的「词速」按钮（`buildButton`）：挂在 `.player-container .extra-controls`，
   找不到时兜底 `document.body.appendChild`。**内容脚本在桌面歌词窗口里也会跑**，
   那个文档根本没有 `.extra-controls`，于是走了兜底分支，按钮被钉在浮动歌词窗的
   左上角 —— 压在歌词上面显示的第二份重复控件。

同批删掉的还有 `showOffset()`：它只更新 `#lyc-val`，而那个元素在删左下角控制条时
就已经不存在了，每次调用都是空转。`openSettingsPanel()` 也失去了唯一的调用方。

## 字体：为什么改了设置里的字体，歌词不变

MoeKoe 的设置里其实有**两项**字体，存进不同的键：

| 设置项 | 存的键 | 管谁 |
|---|---|---|
| 字体设置 | `settings.font` | 界面（按钮、列表、面板） |
| 歌词字体 | `settings.desktopLyricsFont` | 桌面歌词窗口 |

桌面歌词窗口只读后者，而且 CSS 里写死了：

```css
.lyrics-content[data-v-...] { font-family: var(--desktop-lyrics-font-family) !important }
```

在「字体设置」里换成楷体，`--desktop-lyrics-font-family` 根本不会变，
歌词自然纹丝不动 —— 两项各管一头，不是 bug 是设计上就没接上。

插件的做法：优先读 `desktopLyricsFont`，没设就退回 `font`，
算出结果写进 `--lyc-font`，再套到所有歌词面上。这样改哪一项歌词都跟着变，
而应用自己的「歌词字体」仍然优先。面板上的「歌词字体」开关可以关掉跟随。

**特异性要压过应用。** 那条应用规则是 `.lyrics-content[data-v-...]`，
特异性 (0,2,0) 且带 `!important`；写成 `.lyrics-content` 只有 (0,1,0)，
同为 `!important` 时比不过，字体永远不生效。这里把类名连写三遍提到 (0,3,0)。
不用 `[data-v-...]` 是因为那是构建哈希，换版本就对不上。

## 歌词字号不由插件管

一开始以为用户要的是歌词字号，做错了。歌词本来就有大小控制：

| 位置 | 控件 |
|---|---|
| 全屏歌词页 | 设置里的「全屏歌词字体大小」小 / 中 / 大（内联 `font-size` 写在 `#lyrics` 上） |
| 桌面歌词窗口 | 控制条上的 `−A` / `A+` |

要补的是**界面字号**：在「字体设置」里换成楷体之后，界面文字变小、看不清。
插件只补这个缺口，歌词字号一个字都不碰。

## 界面字号

应用只注入字体族，没有字号。源码里 `Pp()` 写的是：

```js
body, html, button, input, textarea, select { font-family: "...", ... !important }
```

所以「字体设置」改完之后字体变了、大小没变，而楷体的字面比默认无衬线小，
于是看着更小。插件在设置页「字体设置」那一行后面插一个滑块补上。

**只改字号做不到。** 界面里 369 处 `font-size` 写死 px（rem 只有 11 处），
靠 `html { font-size }` 继承压不动，逐条覆盖也不现实。所以走整体缩放 ——
Chromium 的 `zoom` 会重新排版，不是 `transform: scale` 那种拉伸。

**缩放要挂在 `html` 上，不是 `#app`。** 挂在子元素上时视口单位不跟着缩放：
`#app` 声明的 `100vh` 仍是整个视口高度，再乘倍率就撑出去，多出来的一截
被裁掉 —— 侧栏下半截（设置 / 更新 / 关于 / 退出）掉到播放条底下，滚也滚不到，
等于把用户锁死在一个再也调不回来的字号里（而那个字号正是在设置页里调的）。
挂在 `html` 上等价于浏览器的页面缩放：视口单位按缩放后的尺寸解析，布局正好
收进可视区，不产生溢出，也就不需要 `height:auto`、`overflow:auto`、
`nav` 滚动之类的补丁 —— 那几个都试过，都不对。

**范围 80~120。** 再往上侧栏最后一项「退出」会被固定在底部的播放条盖住。
120 下七项全可见，实测过。

存的是百分数（滑块原值），读的时候才除以 100。这里翻过车：写成倍率读回来，
`130` 落在倍率区间 `[0.8,1.4]` 之外被判非法，静默退回 100% ——
滑块动了、界面纹丝不动。

### 拖动时不能实时生效

缩放会重排整个应用，滑块自己也跟着挪位。绑在 `input` 上（指针每移动一像素
就生效）的话，滑块会从指针底下跑掉，根本对不准 —— 拖半天出来的值不是想要的。

所以拖动期间只更新右边的百分数，`change`（松手）才真正生效。整个拖动过程
里界面一动不动，滑块不会跑，松手后按最终值一次性重排。键盘方向键同理，
另外回车 / 空格也立刻生效。

单击轨道仍然可用：按下触发 `input`（滑块跳到点中的位置），松手触发
`change`，值照常写进去。

### 设置页那一行怎么插的

克隆一张现成的 `.setting-card` 再改内容，边框圆角背景全跟着应用走。

定位靠标题文字，**不能用相等匹配**：那张卡片的标题里嵌着右上角的帮助图标
（`?`），`textContent` 会带上它，`=== '字体设置'` 永远不成立。要用包含匹配，
并把「歌词字体」排在「字体设置」前面 —— 两张都存在时挨着歌词的是后者。

卡片会被 Vue 重新渲染掉，`mountSettingsRow()` 每 3 秒重扫一次，发现没了就补。

桌面歌词窗口也加载同一个 `index.html`、也有一个 `#app`，`applyUiZoom()`
按路由跳过它 —— 那边有自己的字号控件。

### 两个窗口要各算各的

主窗口和桌面歌词窗口各跑一份 content script，各自持有一份内存里的
`LOOK`。主窗口在设置页改了「歌词字体」，桌面歌词窗口如果一直用启动时读的那份，
就得重开一次才生效。所以 `applyLyricLook()` 每次先 `syncLook()` 从存储同步，
两个窗口才能实时对上。
## 压在图上的控制条要垫一层底

两处控制条是白色图标压在会变亮的背景上：

| 位置 | 容器 | 背景是什么 |
|---|---|---|
| 全屏歌词页 | `.player-controls` | 模糊后的专辑图 |
| 桌面歌词窗口 | `.controls-overlay` | **桌面本身**（那个窗是 `transparent:true`） |

背景浅的时候整排看不见。

按背景亮度动态换色这条路走不通：桌面歌词窗口那层网页读不到桌面像素，
全屏歌词页读到的也只是模糊后的整张图、不是按钮底下那一块。所以给控制条
一块半透明底衬（`rgba(16,16,18,.64)` + 轻微模糊）。

这个透明度是算出来的：压纯白背景得到约 rgb(102,102,102)，相对亮度 0.13，
白图标对比度 **5.4:1**，过 WCAG AA 的 4.5:1。深色背景上几乎看不出变化。

**刻意不加 text-shadow / drop-shadow。** 前面记过为什么：主界面深底上
那圈黑影只会显脏。这里靠的是衬底，不是描边。
